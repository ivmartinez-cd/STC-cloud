Introducción y Hardware

1. Introducción y Arquitectura

STC Cloud implementa un micro-agente de monitoreo denominado STC Cloud Monitor. El agente opera como un servicio del sistema de ejecución silenciosa y bajo consumo de recursos que se comunica de forma segura con la nube para transmitir métricas de uso de impresoras en red local (LAN).

El agente descubre y consulta dispositivos en red local de forma no intrusiva mediante una cascada inteligente de protocolos, priorizando la precisión de datos y la seguridad corporativa.

2. Sistemas Operativos Soportados

El agente está diseñado para ejecutarse como servicio nativo de Windows (mediante NSSM de 64 bits) y es compatible con las siguientes plataformas operativas:

  • Sistemas de Servidor: Windows Server 2016, 2019, 2022 y 2026 (todas las ediciones estándar y datacenters).
  • Sistemas de Escritorio: Windows 10 y Windows 11 (ediciones Pro, Enterprise y Education de 64 bits).
  • Virtualización: Completamente compatible con entornos virtuales VMware ESXi, Microsoft Hyper-V, Citrix, Nutanix y nubes híbridas AWS/Azure.

Cuenta de ejecución: el servicio ("STCCloudMonitor") se ejecuta por defecto bajo la cuenta LocalSystem. Si la política de la organización exige ejecutarlo bajo una cuenta de servicio nominal, se recomienda que esa cuenta tenga contraseña sin expiración: el vencimiento de la contraseña detiene el servicio y, con él, la recolección de contadores.

3. Requisitos de Hardware

Dado que el agente utiliza una persistencia local ligera basada en SQLite de alto rendimiento con optimizaciones del archivo de transacciones (modo WAL), el impacto sobre los recursos es mínimo:

Componente Especificación Mínima Especificación Recomendada
Procesador (CPU) Dual Core de 2.0 GHz (x64) Quad Core de nivel empresarial (Xeon / i5)
Memoria RAM 2 GB de RAM libres para el agente 4 GB de RAM dedicados a servicios generales
Almacenamiento 200 MB de espacio libre en disco 1 GB de espacio libre (para histórico de logs y base temporal)
Tecnología Disco Disco mecánico estándar HDD Unidades de Estado Sólido (SSD / NVMe) recomendadas

Configuración de Red y Firewall

4. Configuración de Red, Puertos y Firewall

El agente utiliza una arquitectura estrictamente Zero-Inbound. Esto significa que bajo ninguna circunstancia se requiere abrir puertos de entrada desde el exterior hacia la red del cliente, lo que reduce la superficie de ataque a cero.

Conexiones de Salida WAN (Hacia el Servidor de la Nube)

El agente requiere resolver nombres de dominio DNS y acceso de salida a través de los siguientes puertos externos:

Puerto Destino Protocolo Dominio de Destino Propósito y Función
443 TCP (HTTPS) ${DOMAIN} (dominio propio de su instalación) Registro inicial del agente, descarga de rangos de red e ingesta de logs.
443 TCP (WSS) ${DOMAIN} (dominio propio de su instalación) Canal persistente WebSocket bidireccional seguro para comandos interactivos y forzar sincronización instantánea.
443 TCP (HTTPS) github.com / raw.githubusercontent.com Acceso al repositorio oficial de actualizaciones para descargar versiones de software seguras.

Conexiones Internas LAN (Hacia las Impresoras de la Red)

Para interrogar y recolectar las lecturas de los dispositivos, el agente utiliza los siguientes puertos locales:

Puerto Interno Protocolo Método / Tecnología Comportamiento y Seguridad
161 UDP (SNMP v1/v2c) SNMP query estándar Lectura rápida de contadores estandarizados y números de serie base.
80 / 443 TCP (HTTP/S) EWS HTTP Scraping Extracción detallada de cartuchos y estados del Embedded Web Server (solo impresoras verificadas).
9100 TCP (RAW/JetDirect) PJL Commands Consulta interna directa de contadores por línea de comandos HP/Canon.
631 TCP (IPP) Internet Printing Protocol Alternativa de consulta moderna basada en solicitudes estandarizadas IPP.

5. Soporte de Proxy Corporativo

En redes cerradas que requieren un intermediario de salida, el agente cuenta con soporte nativo de configuración de Proxy HTTP/HTTPS compatible con túneles CONNECT (necesario para WebSockets seguros). Admite autenticación básica incorporando credenciales cifradas localmente en su archivo de configuración seguro.

Seguridad y Despliegue Masivo

6. Seguridad Criptográfica y Firma Digital

STC Cloud adopta un estándar riguroso de protección de datos en la infraestructura del cliente:

  • Cifrado de Credenciales Locales: Toda la información de configuración (claves del portal, tokens de autenticación de 30 días, etc.) se almacena en el archivo `config.enc` cifrado simétricamente bajo **AES-256-GCM**.
  • Hardware ID Binding: La clave de descifrado no se guarda en el equipo, sino que es derivada dinámicamente mediante **PBKDF2 (210,000 iteraciones)** a partir de parámetros inmutables del equipo host (Windows MachineGuid y Serial Number de la BIOS). Si la carpeta del agente es copiada a otro hardware, los datos no podrán ser descifrados, forzando la desvinculación.
  • Validación Criptográfica de Actualizaciones: El actualizador automático verifica la integridad mediante firmas criptográficas asimétricas **Ed25519** de clave pública fija y hashes SHA-256. Esto neutraliza de raíz los ataques a la cadena de suministro por manipulación del paquete de actualización.

Verificación de Integridad del Instalador (SHA-256)

Para las auditorías de infraestructura que exigen validar el binario antes de distribuirlo, el paquete de distribución incluye el script verify_hash.ps1, que compara el instalador descargado contra el hash SHA-256 oficial de esa versión:

.\verify_hash.ps1 -FilePath "STC-Monitor-Setup.exe" -ExpectedHash "<HASH_OFICIAL_STC>"

El hash SHA-256 oficial de cada versión se publica en el portal STC Cloud y en las notas de lanzamiento. Este control garantiza que el instalador no fue alterado por terceros durante la transferencia.

7. Despliegue Masivo y Silencioso

El instalador de STC Cloud Monitor es compatible con despliegues remotos desatendidos administrados vía directivas de grupo Active Directory (GPO), Microsoft Intune, System Center o herramientas RMM (Datto, Kaseya, etc.).

Ejemplo de Comando de Despliegue Silencioso

Para realizar la instalación de forma desatendida forzando el inicio automático y vinculándolo con los datos del portal en una sola línea, ejecute el instalador con los siguientes modificadores:

STC-Monitor-Setup.exe /VERYSILENT /KEY="LLAVE_DE_ACTIVACION_DE_64_CARACTERES" /SERVER="https://${DOMAIN}"

Explicación de modificadores:
• /VERYSILENT: Oculta la interfaz gráfica y no requiere interacción del usuario.
• /KEY: Registra de inmediato el micro-agente con los identificadores correspondientes del cliente en el portal.
• /SERVER: Establece el endpoint del servidor API en la nube al cual reportará telemetría.

Directorio de Datos del Agente

El agente almacena su configuración cifrada (`config.enc`) y su base de datos local de telemetría en una ruta fija fuera del perfil de usuario, accesible para el servicio y excluible en las políticas de antivirus si la organización lo requiere:

C:\ProgramData\STCCloudMonitor\
